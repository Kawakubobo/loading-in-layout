# Workflow for this live layout project

These instructions record the user's requested working/reference workflow.

At the start of each new user request about this project, before changing implementation files:

1. Run `npm run begin-prompt`. This copies the current working renderer into the reference snapshot and starts a fresh activity session. Do this once per new request, not again for a clarification that arrives during the same request.
2. Keep the reference renderer fixed for the rest of that request. Edit the working files only. Both versions must receive the same current activity feed.
3. Publish visible progress messages and factual tool activity as work happens. Run `node scripts/activity.mjs` with a JSON object on stdin containing `kind` (`tool` or `progress`), `title`, and `summary`. Tool actions are section titles; the corresponding public progress update or concise result is the paragraph content. Use safe shell quoting or pass the JSON through a file.
4. Publish real updates only. Do not add timer-generated filler, rotating sample notes, invented tool actions, or private internal reasoning. This is a manually published public activity feed, not an automatic mirror of hidden model analysis or the Codex UI.
5. Leave both sites available: working at `http://127.0.0.1:4173/`, reference at `http://127.0.0.1:4174/`.

Keep the white canvas at 1920 × 1080, its underlying 12-column Stretch / 5-row layout, 40 px inset and 20 px gutters. Use local Neue Haas Grotesk Display only, 14 px captions, 18 px body copy, and 32/136 px titles and 55 Regular weight (400) for titles, body copy, and captions. Keep guide overlays and general section divider rules hidden; transparent-background images use the horizontal rules specified below. Newest three sections guide placement; more than four text-overlap regions triggers immediate removal of older involved sections. No appearance/disappearance transitions.

Compose the latest three sections with balanced visual weight. Favor optically centered solo sections, opposing left/right or top/bottom pairs, opposite corners, and a dominant section counterbalanced by two smaller sections. Reconsider the current group's positions when content arrives; do not return to arbitrary empty-cell placement. Use rendered text measurements to account for different title sizes and paragraph lengths.

Reveal each new canvas title, caption, and body paragraph character by character like a typewriter. Give each text block a slightly different typing speed (±20% around 32 ms per title character, 24 ms per caption character, and 14 ms per body character). Reveal whole Unicode grapheme clusters. Reserve and measure the complete text from the start so typing does not change wrapping or move the layout. This typewriter reveal is the exception to the no-appearance-transition rule; removal remains immediate, without fades. Keep full text accessible, respect reduced-motion preferences, and cancel pending animation work when content is removed or a session resets. Animate only real published content; do not generate filler activity.

Render captions (section eyebrow labels and footer feed captions) in small caps using `font-variant-caps: all-small-caps`. Keep their Neue Haas Grotesk Display regular weight and 14 px base size. Allow small-cap synthesis for these captions when the local font lacks small-cap glyphs. Keep body copy in its original case.

Render titles in English Title Case: capitalize the first and last words and major words; keep short articles, conjunctions, and prepositions lowercase unless first, last, or following a colon. Preserve acronyms and intentional brand capitalization (such as API and GitHub), non-Latin text, and explicit line breaks. Apply casing before measuring the title for layout.

Always use Neue Haas Grotesk Display 55 Regular (`font-weight: 400`) for titles. Set titles to −2% letter spacing (`letter-spacing: -0.02em`) and 80% line height (`line-height: 0.8`) at every title size, including 32 px and 136 px. Do not override these values in display variants or responsive styles.

Limit each body-copy line to 60 visible characters, including spaces. Count Unicode grapheme clusters so Korean characters, combining marks, and emoji remain intact. Prefer word-boundary breaks and split long unbroken strings when necessary. Render each source paragraph as a separate body paragraph. Do not leave a blank line or extra vertical gap between body paragraphs. Each subsequent paragraph begins on the immediately following line with the normal 120% body leading. Start the first paragraph flush left with no indent; indent the first line of the second and each subsequent paragraph by 2em (36 px). Join single source line breaks with ordinary spaces. Preserve paragraph layout throughout typing. Keep line wrapping for the 60-character limit. Use a body measure spanning exactly three grid columns including the two internal gutters (445 px on the current canvas) and choose line breaks from actual font metrics, accounting for the 36 px first-line indent on later paragraphs. Enforce the 60-character cap as well as the measured width. Optimize the complete paragraph to avoid a staircase-shaped rag and disproportionately short final lines.

Set body copy at 18 px (13.5 pt). Always maintain 120% line height (`line-height: 1.2`) for body copy across layout variants and viewport sizes.

Set body paragraphs flush left with a ragged right edge. Do not justify text. Preserve the 60-character line limit, paragraph indents, and normal 120% body leading without extra paragraph gaps.

Enable automatic English hyphenation in body copy (`hyphens: auto`) using the document's English language metadata. Where supported, hyphenate only words of at least six letters with at least three letters on either side. Keep titles and captions unhyphenated. Preserve the three-column body measure and existing paragraph typography.

Avoid a single-word orphan on the final line of body paragraphs. Penalize single-word final lines when optimizing measured line breaks, redistributing words across earlier lines as needed. Preserve original wording and paragraph indents. If the final pair itself exceeds 60 characters or cannot fit the available width, allow a safe break rather than overflow. Keep the complete wrapping fixed during typewriter reveal.

Type the title first, then body paragraphs sequentially in source order. Each paragraph must finish typing before the next begins. Captions may type alongside the title. Keep each block's slightly varied typing speed and reserve the full text layout throughout.

When a newly placed section overlaps existing text, offset it horizontally by two columns relative to the most recent overlapping section's nearest grid column. Use the 12-column pitch, including gutters: two columns equal 310 px on this canvas. Prefer rightward placement; use leftward placement near the right edge. Keep vertical placement, permit layered overlap, and retain the existing four-overlap cleanup limit. If neither direction fits within canvas margins, preserve the bounded placement. Apply this adjustment after balancing and before overlap cleanup.

Always use the supplied column grid: 12 columns, Stretch, automatic column width, 40 px left/right margins, and 20 px gutters. Calculate column width as `(canvasWidth - 2 * 40 - 11 * 20) / 12` (135 px at 1920 px). If grid guides are shown in a design or inspection view, use #FF0000 at 10% opacity. Keep guides hidden in the normal canvas.

When using a transparent-background photo or image, wrap it in `.transparent-image`. Leave exactly 24 px of vertical space between the image element and a horizontal rule on each side (above and below). Use 1 px solid rules in the current text color, spanning the full image container width aligned to the column grid. Preserve the image aspect ratio and transparency. These measurements use canvas CSS pixels before Fit scaling. The wrapper uses decorative borders, not semantic thematic-break elements.

Fill non-final body lines to their available measured width, accounting only for the actual first-line indent. Do not shorten the first line to equalize it with the final line. A naturally shorter final line is acceptable; still avoid single-word orphans.

Make activity photos prominent: use up to the section's full grid width and 440 px height, preserving aspect ratio. Reduce photo height only as needed to keep the complete image/title/body section within the canvas. Intentionally layer new photo sections over the preceding photo section, offset by two grid columns and 64 px vertically (clamped to canvas margins). Keep some visible overlap rather than separating every section; retain the four-region cleanup limit.

For occasional questions or deliberate emphasis, publish `presentation: "overtext"` explicitly. Render the title as one or two oversized lines on a white foreground layer, intentionally cropped past the canvas edges. This is an exception to grid containment and normal title sizes; retain 55 Regular, -2% tracking, 80% leading, and typewriter reveal. Keep the underlying composition intact and remove the layer on the next event. Do not infer this mode from every question mark. Demo questions must be identified as samples in their summary and must never imply that the user approved an action.

Overtext emphasis must coexist with photos and body copy when photos are available. Use the oversized title as a transparent background text layer, with the latest two photo/text sections in front: a large lower-left photo with copy alongside and a smaller upper-right photo with copy to its left. Restore ordinary layout on the next event. The explicit collage treatment may crop photo frames with object-fit: cover; never stretch them. Keep normal grid guides hidden (the pink columns in the supplied reference are construction guides).

Include occasional editorial-spread moments via `presentation: "editorial"`: a dominant six-column image at left, a three-column text block low in the middle, and a three-column text-over-image stack at right. Derive content from the latest two photo sections, never from the reference screenshot's wording or imagery. Keep white space above the middle text and retain the 12-column grid without showing guides. This is a deliberate composed beat; return to the ordinary layout on the next event. Photo frames use cover cropping, not distortion.

Video exports must contain only the white 1920×1080 artboard. Save the measured artboard bounds and viewport dimensions as capture-region.json beside each frame manifest. The encoder must accept artboard-sized captures, crop known full-viewport captures to those bounds, and hold the last valid canvas frame for unexpected dimensions. Never stretch an entire browser/window screenshot into the output or reuse capture bounds from a different recording session.

Show each real `kind: "tool"` publication as a large transient canvas status above the existing collage, with a short hard off/on beat and a readable hold. Do not replace result sections or reset a photo spread for tool activity. Queue real incoming statuses; clear timers on session reset, avoid replaying stale statuses, and disable blinking for reduced motion. Publish actual public actions (for example, Searching the Web, Ran Commands, Viewed 2 Images) as they occur. This feed is manually published; do not claim to automatically mirror Codex UI events such as compaction or expose private reasoning.

For demo-derived composition preferences, read `DEMO-LAYOUTS.md` before choosing or extending a presentation. Its eight-scene reference maps the user's demo to explicit live presets (`staggered`, `photo-stack`, `type-echo`, `photo-hero`, plus existing `overtext` and `editorial`). Use actual event content and recent photos; never replay demo copy as real progress. A user request to preserve the canvas or skip begin-prompt overrides the default snapshot/reset workflow above.
